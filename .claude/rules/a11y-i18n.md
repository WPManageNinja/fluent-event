# a11y-i18n — accessibility + internationalization

Applies to every Vue / frontend UI change.

## i18n

- Every user-facing string runs through a translation helper. Text domain: `fluent-events`.
- **PHP**: `__('Text', 'fluent-events')`, `_x('Text', 'context', 'fluent-events')`,
  `_n('one', 'many', $count, 'fluent-events')`.
- **Vue**: the app's `$t('Text')` mixin (reads the server-supplied translation map) —
  not raw `__()`, not `vue-i18n`. Plurals via the `$_n('1 item', '%d items', $count)`
  mixin. Match the existing pattern.
- Don't hardcode English in Vue templates — it bypasses translation entirely.

## Escape-after-translate

- `__()` / `_e()` output is NOT sanitized — a translator can return HTML. Wrap with
  `esc_html__()` / `esc_attr__()` / `esc_html_e()` / `esc_attr_e()` as fits the sink.
- Vue `{{ }}` / `v-text` already HTML-escape — fine for translated strings.
- **Never** `v-html="$t('...')"` on user-displayed strings — render-time XSS via a
  malicious translation. See [vue.md](vue.md) and [fix-patterns.md](fix-patterns.md).

## Placeholders

Use `sprintf` placeholders; don't concatenate translated fragments (word order varies
by language):

```js
// BAD
{{ $t('Hello ') + name }}
// GOOD
{{ $t('Hello %s', name) }}
```

Add a `/* translators: %s is the user's first name */` comment in the PHP `__()` call
when context is non-obvious.

## a11y — semantics

- Icon-only buttons need `aria-label` (or visible text):
  `<button :aria-label="$t('Close')"><i class="icon-close" /></button>`.
- Form inputs have an associated `<label>` (or `aria-label` if icon-only).
- Status/error messages use `role="status"` / `role="alert"` so screen readers announce.

## a11y — focus + keyboard

- Modal opens → focus moves into it; closes → focus returns to the trigger.
- Every interactive element reachable by Tab; Enter/Space activates, Escape closes
  modals/dropdowns. Don't override default keyboard behavior without an equivalent.

## a11y — visual

- Visible focus outline on every interactive element — no `outline: none` without a
  replacement.
- Color is never the sole indicator (pair red text with an icon, etc.).
- Contrast holds in BOTH light and dark mode — use the theme CSS variables, not
  hardcoded hex (see [vue.md](vue.md) theming).
- Every `<img>` has `alt` — decorative `alt=""`, informative describes the meaning;
  avatars use the member's display name.

## Translation dedup

- One canonical translation per concept. The same `$t('...')` literal repeated across
  files drifts — hoist it (constant / computed / shared prop). Same English with
  different `_x()` contexts is valid; document each with a `/* translators: */` note.

## Self-audit

1. Every string via `$t()` (no hardcoded English in templates)?
2. PHP translations wrapped with `esc_html__` / `esc_attr__` at the sink?
3. `sprintf` (`%s`/`%d`) for parameters, not concatenation? Plurals via `$_n`/`_n`?
4. Icon buttons have `aria-label`; inputs have labels?
5. Modal focus managed; keyboard-reachable; visible focus?
6. Images have `alt`?
7. No `v-html="$t('...')"`; no duplicate `$t()` literals across files?

**Not hook-enforced** — self-audit discipline (the scanner has no a11y/i18n rule).
